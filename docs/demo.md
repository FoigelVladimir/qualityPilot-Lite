# Демонстрация QualityPilot Lite за 3–5 минут

До демонстрации выполните [установку и полный pipeline](../README.md#3-данные-и-воспроизведение-эксперимента).
Нужны локальные bottle, baseline и COMPLETE PatchCore run. Запустите
`uv run --no-sync python -m streamlit run app.py`; в боковой панели выберите
полученный run. Исторические папки из отчётов не поставляются с Git.
Все примеры ниже — **известные демонстрационные данные из test**, не новая оценка.

1. **0:00–0:45 — baseline.** Откройте «Проверка изображения», выберите Baseline,
   «Локальный тестовый пример», broken_large / `000.png`, нажмите «Проверить».
   Покажите score и ACCEPT/REVIEW/REJECT. В историческом run этот дефект получил
   ACCEPT: глобальные признаки пропускают локальную аномалию. Baseline не имеет карты.
2. **0:45–1:45 — PatchCore на том же файле.** Выберите PatchCore, снова нажмите
   «Проверить». Покажите фактический device, score, пороги и решение. Для исторического
   run score ≈19.7674 и REJECT. Для своего run используйте фактическое значение UI.
   Найдите heatmap, overlay, predicted mask и GT. Карта не является точной сегментацией;
   оценка Dice около 0.56. Измените прозрачность: score не пересчитывается.
3. **1:45–2:30 — временная политика.** Включите экспериментальные пороги,
   оставьте accept прежним и увеличьте reject выше текущего score
   (например, до 30 для исторического примера). Рекомендация станет REVIEW,
   исходное решение и score сохранятся. Нажмите «Сбросить». Объясните, что это
   демонстрация политики, а не настройка модели по test и не улучшение метрик.
4. **2:30–3:30 — saved reports.** Откройте «Результаты эксперимента»:
   сравните AUROC/F1, confusion matrices, REVIEW и latency. Покажите FP, затем FN:
   у PatchCore исторически FN=0, поэтому фиктивного FN-примера нет.
   Single threshold даёт 4 FP несмотря на AUROC 1.0. Таблица читается без весов.
5. **3:30–4:30 — границы.** Вернитесь к good / `000.png`, проверьте normal-пример.
   При наличии времени загрузите JPG/PNG: GT для upload неизвестна. Откройте
   «О проекте»: только bottle, 83 test-изображения, сторонний источник данных,
   normal-only калибровка, отсутствие гарантий FPR/recall и промышленной проверки.

Не сравнивайте численно scores двух моделей: их шкалы различаются. Одиночное время
UI зависит от загрузки/декодирования и не заменяет benchmark с прогревом.
Иллюстрации и screenshots с MVTec остаются локальными в ignored evidence;
публичная документация использует только текст и схему.
