# Демонстрация QualityPilot Lite за 3–5 минут

Выполните [установку и полный pipeline](../README.md#3-данные-и-воспроизведение-эксперимента).
Нужны локальные bottle, baseline и COMPLETE PatchCore run. Из корня проекта:
`uv run --no-sync python -m streamlit run app.py`.
Откройте http://127.0.0.1:8501, раскройте в боковой панели **«Настройки проверки»**
и выберите свой сохранённый эксперимент по дате UTC и уникальному окончанию.
Полное имя находится в технических подробностях; исторические папки с весами
не поставляются с Git. По умолчанию выбраны PatchCore и автоматическое устройство.
Все примеры ниже — **известные демонстрационные данные из test**, не новая оценка.

1. **0:00–0:45 — базовая модель.** В настройках выберите «Базовая модель
   (Isolation Forest)». На странице «Проверка изображения»: «Пример из датасета»,
   «Крупное повреждение», `000.png`. Под превью нажмите **«Проверить изображение»**.
   В историческом run показаны 0,49 и «Рекомендуется принять» (ACCEPT): модель
   пропускает этот дефект. Низкая аномальность не гарантирует исправность.
   Эта модель оценивает снимок целиком и не выделяет области.
2. **0:45–1:45 — PatchCore на том же файле.** Выберите PatchCore в настройках
   и снова нажмите «Проверить изображение». Исторический результат — 19,77,
   «Рекомендуется отклонить» (REJECT); устройство показано рядом. Точное значение
   19.76740837097168, пороги и время раскрываются в «Технических подробностях».
   Для своего run используйте фактические значения. Оценка не является вероятностью.
   Ниже сравните оригинал и «Наложение», измените прозрачность. Переключите
   «Тепловая карта», «Контур подозрительной области», «Бинарная маска».
   Включите «Крупный просмотр» и выберите результат либо оригинал; Fullscreen
   открывает штатный полноэкранный просмотр. При необходимости включите
   «Сравнить с разметкой дефекта». Общая шкала и порог карты фиксированы;
   контур — представление той же маски, а не улучшение сегментации (Dice ≈0,56).
   Эти переключения не запускают повторный inference.
3. **1:45–2:30 — временная политика.** Раскройте «Экспериментальные пороги»,
   включите «Включить временные пороги». Оставьте accept прежним, увеличьте reject
   выше score, например до 30 для исторического примера. Временная рекомендация
   станет «Нужна ручная проверка» (REVIEW); исходный REJECT и score останутся.
   Нажмите «Сбросить к порогам модели»: временная политика выключится.
   Это демонстрация политики на известном test, не настройка модели и не
   улучшение исторических метрик. Значения не записываются в файл.
4. **2:30–3:30 — сохранённые отчёты.** Откройте «Результаты эксперимента»:
   сравните AUROC/F1, русские матрицы ошибок, долю ручной проверки и время.
   Раскройте «Как читать метрики» для Precision/Recall/FPR. В «Тип результата»
   выберите «FP — ложная тревога», затем «FN — дефект пропущен». У исторического
   PatchCore FN=0: честно показано отсутствие случаев. AUROC 1,0 не отменяет
   4 FP при сохранённом пороге. Таблицы читаются без загрузки весов и ML extra;
   временные пороги страницы проверки на них не влияют.
5. **3:30–4:30 — нормальный пример и загрузка.** Вернитесь к проверке,
   выберите «Исправная бутылка», `000.png` и снова нажмите кнопку. У исторического
   PatchCore — 8,04, «Рекомендуется принять». Для своей фотографии выберите
   «Загрузить фотографию», нажмите Browse files либо перетащите JPG/PNG
   (до 10 МиБ и 20 млн пикселей). Разметка дефекта для загрузки неизвестна.
   При повреждении файла появится понятная ошибка; разделы остаются доступны.
   «О проекте» объясняет ограничения: bottle, 83 test-примера, сторонняя копия,
   normal-only калибровка и отсутствие гарантий для других камер.

Смена изображения, модели, эксперимента или устройства сбрасывает прежний результат;
для нового входа нужна кнопка проверки. Смена модели/эксперимента сбрасывает
временные пороги. При отсутствии весов или данных UI объясняет причину;
скачивание и обучение из браузера не запускаются.

Не сравнивайте численно оценки двух моделей: их шкалы различаются. Одиночное
время UI не заменяет benchmark с прогревом. Русифицированы прикладные подписи;
Browse files, Drag and drop file here, Fullscreen и меню таблиц — системные строки
Streamlit. Историческая техническая иллюстрация в раскрываемом блоке может иметь
английские подписи. Иллюстрации и screenshots с MVTec остаются в ignored evidence;
публичная документация использует текст и схему.
