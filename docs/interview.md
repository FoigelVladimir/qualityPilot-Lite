# Как объяснить проект на собеседовании

**Задача и выбор anomaly detection.** Нормальных изделий обычно больше,
чем размеченных дефектов; новые виды дефектов заранее неизвестны. Здесь методы
обучаются на normal train и оценивают отклонение от нормальных признаков.
Это учебная постановка на MVTec AD bottle, без заявления промышленного внедрения.

**Почему PatchCore.** Предобученный frozen backbone даёт признаки локальных патчей.
Нормальные признаки собираются в memory bank; coreset уменьшает память и стоимость
поиска соседей. Расстояния до нормальных патчей дают score и карту. ResNet18 выбран
как компактный вариант для RTX 3050 8 GB. PatchCore с нуля не разрабатывался:
использован нативный `PatchcoreModel` Anomalib 2.2.0.

**Зачем baseline.** Isolation Forest на 60 глобальных RGB/текстурных признаках
проверяет, насколько сложный метод нужен вообще. Он дешёвый, работает без Torch,
имеет прозрачный preprocessing и показывает ограничение глобальных признаков:
локальный дефект может мало менять статистику всей бутылки. Он не локализует дефекты.

**Train / calibration / test.** Из 209 official train/good seed 42 отделяет
167 train и 42 calibration. Test — неизменённые 83 изображения: 20 normal и
63 defect. Manifest фиксирует порядок, пути, метки и хеши RGB; проверки исключают
пересечения и точные дубликаты. Near-duplicates не проверяются.
Test не используется для обучения или выбора порогов. Однако сравнение post-hoc:
baseline test уже был известен при создании PatchCore, повтор Sprint 4 не независим.

**Normal-only калибровка.** Image accept/reject — эмпирические квантили 0.95/0.99
normal calibration, метод `higher`. Pixel threshold — 0.99-квантиль максимумов
нормальных карт. Так test masks не участвуют в выборе порога. На 42 изображениях
верхние квантили грубые; этот способ не оптимизирует Dice, не оценивает recall
дефектов и не даёт конечновыборочной гарантии будущего FPR.

**Почему AUROC 1.0 и одновременно 4 FP.** AUROC оценивает ранжирование по всем
порогам. На известном test PatchCore ранжировал дефекты выше normal, но заранее
выбранный accept оставил четыре normal выше порога: FPR 4/20=0.20, precision
63/67≈0.9403. Порог для максимального test F1 не подбирался. При двух порогах эти
четыре normal идут в REVIEW; их ручной исход неизвестен. REVIEW не равен исправлению.

**Что означают Dice/IoU.** Micro Dice≈0.5604 и IoU≈0.3893 рассчитаны на native
224×224, включая normal. Pixel AUROC≈0.9760 показывает хорошее ранжирование пикселей,
но фиксированный порог и пространственно сглаженная карта могут захватывать лишнюю
область. Это умеренная локализация, а не точная сегментация границ на исходных 900×900.
GT для метрик уменьшена nearest-neighbour; UI возвращает карту в исходную геометрию.

**Компромисс качества и скорости.** В сопоставимом Sprint 2 baseline CPU median
22.01 ms, PatchCore CUDA 28.61 ms, PatchCore CPU 48.31 ms: batch 1, три прогрева,
decode/preprocessing включены, CUDA синхронизируется. Hardware разный, это не
изолированное сравнение стоимости алгоритмов. PatchCore заметно повышает recall
(0.5714 → 1.0 на этом test), требует Torch, pretrained-весов и memory bank.
Загрузка модели и UI rerun в benchmark не включены; первые запросы дороже.

**Собственный код.** Импорт и provenance, валидация данных/масок, split/manifest,
60 признаков baseline, интеграция Isolation Forest, normal-only пороги,
адаптер PatchCore, сохранение/reload, общий Inspector, image/pixel metrics,
matched benchmark, визуализация, Streamlit state и валидация отчётов, тесты/CI.
Isolation Forest реализован scikit-learn. ResNet и preprocessing-примитивы —
timm/torchvision; извлечение патчей, coreset, nearest-neighbour scoring и карты —
Anomalib. Engine/MVTecAD datamodule/postprocessor не подключены, чтобы явно
контролировать split и калибровку.

**Следующий шаг при настоящем внедрении.** Собрать отдельные данные других камер,
дат/партий и дефектов, определить стоимость FP/FN и ручной проверки, выделить
независимый validation/test, проверить устойчивость и дрейф. Это направления
будущей работы, не выполненные возможности проекта.
