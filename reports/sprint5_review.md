## Замечания

**P0/P1:** в проверенном изменении не обнаружены. Это не гарантия отсутствия
ошибок во всех сценариях приложения.

**P2 — числовая сортировка таблицы.** В
`src/qualitypilot/ui/presentation.py::prediction_table` score и времена
превращаются в строки с запятой. Независимый пример сортировки отображаемого
DataFrame даёт `19,77 → 8,04 → 9,10`: порядок строковый, не числовой.
Это мешает искать максимальные score/время через таблицу, но не меняет
фильтрацию, решения и сохранённые метрики. Исправление: сохранять числовой dtype,
а два знака задавать через настройки отображения числовых колонок Streamlit.

**P2 — видимость контура.** Граница рисуется толщиной один исходный пиксель
цветом `(255, 210, 0)`. При отображении снимка около 900 px в колонке около
320 px линия становится тонкой и плохо различается на светлом фоне; это
видно на проверенном `broken_large/000.png`. Исправление: сделать обводку
контрастнее и/или добавить толщину только в изображение для просмотра.
Исходную маску, порог и pixel metrics менять для этого не требуется.

## Оценка проекта для собеседования

Проект даёт хороший материал для собеседования на стажировку или junior
ML/CV-позицию: есть полный путь от данных до демонстрации, простой baseline,
PatchCore, раздельная калибровка и оценка, анализ ошибок, повтор эксперимента,
тестируемое приложение и честное описание ограничений. Архитектура соразмерна
учебной задаче; переход на микросервисы или другой frontend не нужен.

Сам репозиторий не подтверждает самостоятельное владение материалом. На
собеседовании стоит проверить, может ли автор объяснить memory bank,
normal-only калибровку, отличие AUROC от качества при фиксированном пороге,
прочитать код Inspector и самостоятельно внести небольшое изменение.
Использование Codex следует описывать прямо, с указанием собственной роли.

Это не доказательство промышленной готовности или уровня middle. Остаются
одна категория, небольшой известный test и отсутствие независимой проверки
других условий съёмки. Повтор на том же test подтверждает воспроизводимость,
а не переносимость на новые данные.

## ML и следующий этап

Исторические Image AUROC 1.0 и recall 1.0 PatchCore на bottle правдоподобны
в рамках указанного протокола, но при accept остаются четыре ложные тревоги
из 20 исправных снимков. Dice 0.560382 и IoU 0.389257 показывают умеренное
совпадение областей: высокая полнота покрытия дефекта сочетается с большой
лишней выделенной областью. Новый контур эту проблему делает удобнее для
осмотра, но не исправляет.

Продолжать можно. Следующий полезный этап — ограниченный анализ ошибок
локализации и заранее заданный протокол проверки возможных улучшений.
Известный bottle test уже многократно просмотрен: выбранное по нему улучшение
нельзя выдавать за независимо подтверждённый прирост. До новых вариантов
нужно определить отдельные данные для настройки и итоговой оценки.
Два замечания P2 можно устранить небольшим UI-патчем без отдельного большого
спринта; они не блокируют публикацию текущего результата.
