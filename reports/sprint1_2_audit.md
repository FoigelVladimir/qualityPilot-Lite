## Проверка фактического ML-потока

Проверена логика вызовов, а не только флаг test_used_for_tuning:

1. `prepare` воспроизводимо выделяет calibration только из train/good; официальный
   test сохраняется. Чтение test labels/masks при inventory — проверка структуры,
   не источник параметров модели или порога.
2. `run_patchcore` вызывает `normal_paths` отдельно для train/calibration.
   Gate проверяет split, label=0 и реальный префикс пути category/train/good.
3. В `backend.fit` поступают только train paths; feature extraction и coreset
   используют только их embeddings. Предобученный backbone не оптимизируется.
4. Calibration loop проходит только calibration paths, получает scores и
   максимумы native maps. Квантили 0.95/0.99 и pixel 0.99 берутся из config,
   не выбираются по метрикам test.
5. Сохранение model.pt с metadata/thresholds, experiment.json и reload-check
   на calibration предшествуют первому вызову test evaluation.
6. Test labels используются в evaluation после фиксации модели и порогов.
   Test masks используются для пиксельных метрик и иллюстраций, не для fit/calibrate.
7. Загрузка baseline использует его готовый joblib; сравнение не переобучает
   baseline и проверяет одинаковые paths/labels и исторические scores.
8. Preprocessing детерминирован, без crop/rotation; GT уменьшается nearest-neighbour.
   Карты остаются в native 224×224 для метрик и bilinear возвращаются в исходную
   геометрию для отображения. Размеры исходных изображений и GT повторно совпали.

Проверенный код и согласованные артефакты не показывают настройки по test.
Внепрограммную историю ручных решений невозможно доказать одним аудитом;
поэтому сравнение остаётся описательным post-hoc, как и в историческом отчёте.

Правила неопределённых метрик и пустых масок:

- Для normal отсутствие маски означает нулевую GT; не изображение «без разметки».
- Для defective отсутствующая/пустая, небинарная или неверного размера маска —
  ошибка валидации, её нельзя молча заменить нулевой.
- Pixel AUROC требует обоих классов пикселей; иначе null и причина.
- Dice/IoU — micro по всем test pixels, включая normal. При пустой GT и пустом
  prediction во всём оцениваемом наборе знаменатель нулевой: N/A, не фиктивная 1.0.
- Без независимого pixel threshold Dice/IoU — N/A; baseline без карт — N/A.
- Неопределённые precision/recall/F1/FPR и AUROC представлены null с причиной.

## DeprecationWarning Anomalib

Исследован установленный исходник, зависимость не обновлялась:
`anomalib/models/image/patchcore/torch_model.py:250–251` объявляет
`@deprecate(args={"embeddings": None}, ...)` и `embeddings=None`.
В `anomalib/utils/deprecation.py:212–217` декоратор вызывает
`bound_args.apply_defaults()`, добавляя embeddings в список аргументов.
Затем `_warn_deprecated_arguments` (строки 130–137) предупреждает просто при
наличии имени в bound_args, независимо от того, передал ли его вызывающий код.

QualityPilot передаёт только sampling_ratio. Замена этого корректного вызова
на позиционный не устраняет причину. Обход декоратора через __wrapped__, патч
site-packages или смена алгоритма ради предупреждения не применялись.
Без изменения upstream нет необходимости в такой правке. Предупреждение не
подавлялось глобально и сохранено в логе ML-тестов; runtime inference его не требует.
